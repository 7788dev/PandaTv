## 逐条去广告审阅

本表是对见界原规则的首轮结论；其中“已验证 CDN”“生效期”“限定 lzi”三处已被下文复审推翻，以复审为准。

| 原规则 | 证据与复用结论 |
| --- | --- |
| 路径 token `ad` | 不匹配域名、不校验业务上下文，可能命中合法目录或散列子目录；Panda 不做通用删除 |
| `ads` | 同上，未在本次样本命中；不做通用删除 |
| `adv` | 同上；不做通用删除 |
| `advert` | 同上；不做通用删除 |
| `gg` | 特别容易命中普通缩写；不做通用删除 |
| `guanggao` | 无独立样本佐证；不做通用删除 |
| `sponsor` | 可能为正片赞助信息/节目组成；不做通用删除 |
| `promo` | 可能为用户所选预告内容；不做通用删除 |
| `adjump` | bfzy 真实命中；限定 sourceKey=bfzy、已验证 CDN hostname 和完整路径段 `/video/adjump/time/`，禁止子串域名匹配 |

| `# ppvod-ad-injected` | lzi 两样本仍出现；限定 lzi 和闭合边界，删除对应分片，保留两侧内容；不依赖目录异常启发式 |

## 生产实现接口与清单

- `PlaybackService.availability(item: MediaItem): Promise<{ episodes?: number; episodeTitles?: string[] }>`：根据源精确匹配详情得实际可播集数；不得把豆瓣总集数当可播集数。
- `PlaybackService.resolve(item, episode, quality?): Promise<Playback>`：内部全源搜索、名称/年份/类型校验、真实 HLS/MP4 探测；仅返回能力 URL，原 URL/请求头不进入渲染进程。
- `MediaProxy.registerImage(url): string`：主进程校验豆瓣图片域名，返回不透明本地能力 URL；`registerMedia` 内部使用。
- 主进程请求预算/超时/重试、缓存及并发限制；公共 DNS/IP/重定向检查防 SSRF；Range 流式转发、HLS 所有 URI/key/map 重写，禁止传递 Set-Cookie。
- 解析 ac=videolist/ids、`$$$` 分线路、`#` 分集与 `$` 名称URL；仅保留 HLS/MP4；搜索只做播放发现，不把 CMS 分数/海报冒充豆瓣数据。
- 自动化测试覆盖精确域名与近似域名、广告前后保留、真实样本规则命中、加密/多轨/直播不变、首尾/中间/切集请求、同名翻拍/类型冲突、ids 被忽略、失败显式错误。

## 复审与规则 v2（2026-11-16，取代上文的“已验证 CDN + 生效期”方案）

上文方案落地后重新对线上清单抽样，发现它基本失效，已改写。事实与处理如下，全部可用 `npm run audit:ads` 重放，结果写入 [ad-audit.json](evidence/ad-audit.json)。

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 规则按 CDN 域名白名单生效，而每个源都在轮换 CDN 域名 | 改写前 82 份线上清单只有 15 份被过滤，其余因域名不在名单内整份放行 | 删除 `ruleHosts`；规则只按源 key 生效，证据来自清单结构本身 |
| 带 AES-128 的清单一律不过滤 | bfzy、360zy 的加密正片里插入的是未加密广告块 | 逐段跟踪 `#EXT-X-KEY`，可删除明文插入块；解密实验确认 bfzy 隐式 IV 按不含广告的正片序号编号，删除后解密不受影响；若被删段本身加密且无显式 IV，则整份保留（`encrypted-implicit-iv`） |
| `rulesExpireAt` 到期后全部规则静默关闭 | 到期只和日历有关，和规则是否仍然正确无关 | 删除按时间失效；改为可重放审计 + 用户数据目录规则覆盖 |
| dyttzy 只有一个指纹 | 新样本出现第二种 4 段广告 `[6.667,2.133,3.233,3.733]`，[画面](evidence/ad-frame-v2-dyttzy-2-2.jpg) 为博彩广告 | 加入第二指纹，容差收紧为 ±0.04 s 且必须两侧都有 discontinuity |
| ppvod 标记只认 lzi | bfzy 新清单同样带 `# ppvod-ad-injected`，[画面](evidence/ad-frame-v2-bfzy-2.jpg) | 标记对所有源生效，只作用于下一个 discontinuity 打开的那一块 |
| bfzy 路径规则绑定在 CDN 域名名单上 | 5 份 bfzy 样本的广告段全部在 `/video/adjump/time/` 下（54 段），但域名已换 | 源级 `adPaths` 前缀 `/video/adjump/`（该源的广告专用目录），与域名无关，只接受完整目录层级 |

## 片源身份匹配复审（2026-11-16）

在安装版上实测时，搜索《凡人修仙传》得到的第一条动画《凡人修仙传 年番4》65 秒内没有起播。原因不在播放器，而在“豆瓣条目 → 片源记录”的身份匹配。逐项事实与处理（实现见 [service.ts](../src/main/playback/service.ts)，决策与备选方案见[决策记录](../.agents/notes/implemented/architecture/2026-11-16-source-identity.md)）：

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 豆瓣把长篇连载按年拆成多个条目，片源只有一条从第 1 集累计编号的记录 | 《凡人修仙传 年番4》（2026，52 集）在 5 个源里都只有《凡人修仙传》（2020，200 集）；豆瓣详情 `aka` 给出“凡人修仙传 第177-228集” | 读取 `aka` 里的集数区间（“第N-M集”“N-M集”“第077-128集”等写法），在同名、同类型、年份不晚于条目的累计记录上取第 N…M 集并从 1 重新编号；只用逐集带编号的线路 |
| 同名记录比豆瓣条目多出后续内容 | 《凡人修仙传：外海风云》豆瓣 28 集，一个源在同名记录下列了 52 集 | 一旦按区间找到累计记录，其余同名记录截到同样的集数，无编号的列表不参与 |
| 一条混入特别篇的线路成为选集基准 | 《斗破苍穹 第一季》一个源的线路为 12 集 + 2 个特别篇（14 项、无法按编号对齐），因条数最多被选为基准，其余 5 个源的 12 集编号线路全部被排除，而该线路自身不可达，结果是“片源暂时无法连接” | 基准线路只在“逐集编号”或“每项都有自己名称（按期日期、分段名）”的线路里选；只是顺序的混合列表仅在没有别的线路时使用 |
| 媒体代理只放行 80/443 端口 | 金鹰资源的分片在 `c.baisiweiting.com:18443`，飘零资源一条线路同样被拒；金鹰是《斗破苍穹：双帝之战》唯一的片源 | 与浏览器一致：放行 80、443 和 1024 以上端口，拒绝 Fetch 标准列出的高位“坏端口”与其余低位端口；公网地址校验与 DNS 固定不变 |
| 豆瓣标题末尾带零宽字符 | “斗破苍穹剧场版 双帝之战”“凡人修仙传：外海风云”末尾各有一个不可见字符 | 比对与检索前去掉零宽/方向控制字符 |
| 豆瓣与片源的年份差一年 | 《生命奇观》豆瓣 2023，两个源均为 2024 | 名称与分类完全一致、年份只差一年视为弱匹配；别名（含港台译名，去掉“(港)”“(台)”标注）加年份、分类一致同为弱匹配。弱匹配只在没有任何精确匹配时采用 |
| 累计记录里夹着少量附加项 | 《斗罗大陆》的累计记录在 6 个源里有 5 个带“第240集上/下”“90分钟结局”“导演剪辑版”等两三项；原先要求整条线路逐项带编号，分年条目因此只剩电影天堂一个源，其媒体主机一次不可达就整季“片源暂时无法连接” | 取区间时跳过无编号的附加项、不用重复出现的编号，带编号条目不足九成的线路仍不用；“第40集完结”读作第 40 集。改后同一条目有 5 个源可用 |
| 单个源一次不答复被当成“没有片源” | 《生命奇观》《斗破苍穹：双帝之战》只有金鹰资源收录；该源一次超时或返回 404 页面，结果即为“未找到可用片源”并缓存 20 秒 | 没有结果且有源失败时，1 秒后只追问失败的源一次；仍有源“刚开始失败”（未满 2 分钟）时提示“暂时无法连接，请重试”且不缓存；持续失败超过 2 分钟的源不再影响结论。见[决策记录](../.agents/notes/implemented/architecture/2026-11-16-source-verdict.md) |

改动前，带区间别名的分年条目全部找不到片源。改后各分年条目的可播集数与豆瓣区间一致（《凡人修仙传 年番4》为第 177–200 集共 24 集，外海风云 28 集，魔道争锋 25 集）。热门未通过的条目逐条查过各源的检索结果，均为确未收录（《夫妻一场》在片源里是另一部 2024 年的同名剧，不匹配是正确的）。同一脚本当天先后跑了五轮，轮与轮之间有 1–7 个条目因某个源当时不答复而变化，这正是下面两行处理的问题。离线回归见 [source-alias.test.ts](../tests/source-alias.test.ts)、[source-match.test.ts](../tests/source-match.test.ts)、[source-requery.test.ts](../tests/source-requery.test.ts)；安装版上的真实动画起播见 [install.txt](evidence/install.txt)。

仍然存在的边界：没有区间别名的条目只能按标题匹配，累计记录会把整部连载的集数都列在该条目下（《吞噬星空 第1季》豆瓣 26 集，片源列 249 集；《斗罗大陆Ⅱ绝世唐门 年番1》豆瓣 52 集，片源列 179 集；前若干集对应正确）；按别名找到的分篇记录编号可能与豆瓣条目不一致，所以只在没有更强证据时使用；被拆成上下两段的一集在该线路上没有对应项。只有一个源收录的作品在该源故障期间无法播放，界面提示重试。

## 片源与起播复审（2026-11-17）

起因：要求“随便点一个都能播”，且实际使用环境在国内，而开发机的出口在境外。测量方法、各源数据和四轮起播结果在 [cn-sources.md](evidence/cn-sources.md)，设计取舍在[决策记录](../.agents/notes/implemented/architecture/2026-11-17-source-contest.md)。

| 发现 | 证据 | 处理 |
| --- | --- | --- |
| 候选源里“金鹰系”（速播、虎牙、红牛、光速、新浪、豪华、极速）是同一批编码，快慢相差数倍 | 北京实测起播中位 0.6–2.7 秒 | 只加最快的三家；极速仍停用 |
| 360zy 在国内解析到 `127.0.0.2`，飘零接口关闭 | 系统解析与公共解析一致；接口答复 `closed` | 360zy 保留（境外出口下最快）并识别为“此网络不可达”；飘零停用 |
| 清单声明的分辨率与实际不符；同一个源不同作品画面不同 | 首片 SPS 与清单 RESOLUTION 对比；《奥德赛》864x326 对 1920x1080 | 从首片读实际画面再选源，标签用实际画面 |
| 红牛的分片在 65 端口 | `hnts.ymuuy.com:65` | 端口规则与浏览器一致，见[端口记录](../.agents/notes/implemented/architecture/2026-11-16-media-ports.md) |
| 完结剧最后一项写作“第30集已完结”，整条线路被判为无法按集号对齐 | 新增三家与金鹰在完结剧上缺席 | 集号解析接受“已完结 / 完结 / 大结局” |
| 一个目录拖满 9 秒时所有起播都等它 | 北京 14:17 一轮搜索中位 2.9 秒、最慢 11.7 秒 | 找到后最多再等 1.2 秒；改后同一时段中位 1.3 秒 |
| 没有片源的作品被报成“暂时无法连接” | 《骑有此理 第四季》九个源都没有收录 | “没答复”只按本次搜索算，见[片源结论](../.agents/notes/implemented/architecture/2026-11-16-source-verdict.md) |
