## 歧义与最小处理依据

- **清晰度**：原型演示始终四档，契约明确实际可选少于两档不显示按钮。以契约为准；设置仍保存质量偏好，不暗示片源具备该档。
- **集数**：契约 `episodes` 指实际能播集数，不是豆瓣总集数。豆瓣metadata与播放源能力应分别获取，详情选集以验证的源集数呈现；不得按元数据伪造可播集。
- **缺图/缺字段**：缺海报按原型显示片名文字卡，缺横图用真实海报氛围底，均无图则留真实片名与墨底；不代入演示海报。评分、年份、角色、简介缺失时不输出元素。`channel.empty` 的“暂无内容”是规定空态，区别于字段占位。
- **演员头像**：Person只声明name/role，原型使用名字首字，保持该设计，不私自引入头像模块。
- **检查更新**：只有实际版本源校验成功才可提示最新；未配置/失败用短错误toast，不能复制演示成功反馈。
- **错误/离线/加载**：页面截图未逐一提供，但 kit+公共样式+copy 已规定骨架/图标/一行文字/最多一个按钮。沿用已有组件，不添加说明长文或新模块。
- **截图尺寸**：19张导出图均2160×1352；列数显示7列，说明截图导出倍率不等于CSS视口宽。像素对比须固定CSS视口/DPR/字体加载，不能用2160 CSS像素直接比较；优先通过原型实际浏览器复现对应布局。
- **历史下一集**：契约 `historyRecord` 将95%后记为下一集0秒但沿用当前duration；当前duration只能用于原始记录，下一集真实duration需metadata后重写，不能当未来集时长。

- UI 本地状态通过主进程持久化并在renderer订阅，不直接对设计契约的localStorage说明实施机械复制。需要 user.get、toggleFavorite、recordHistory、remove/restoreHistory、clearHistory、add/clearSearch、updateSettings；状态写入失败必须显露。

## 还原结果（2026-11-16，实现完成后）

对照方式：同一个 Electron 进程里同时打开原型（`design/preview`，只在 e2e 的 fixture 主进程里加载）和生产界面，喂同一份 fixture 数据，1440×901 视口，逐场景成对截图并比较关键元素的盒模型。实现见 [fixture.spec.ts](../e2e/fixture.spec.ts)；截图与盒模型数据在 [evidence/visual](evidence/visual/overlay-report.json)，数字汇总在 [final-verification.txt](evidence/final-verification.txt)。fixture 与原型加载器都不进入发行包。

- 19 组截图覆盖原型 01–17、19 号状态（05 号分“集标题列表”与“分段选集”两组）。18 号“缓冲中”是瞬时状态，没有成对截图。
- 非播放页 16 组的像素差异（任一通道相差超过 24/255 的像素占比）在最终一轮（20:07）为 0–0.40%，多数为 0，超过 0.17% 的三组都是带海报的页面（首页、频道、联想）；各轮之间随图片淡入时机有零点几个百分点的波动，当天见过的最大值 0.38%。
- 播放页 3 组（暂停、选集面板、下一集提示）画面内容不同，差异 14–19% 来自视频画面本身；控制栏、进度条、面板、提示卡等 16 个被测盒子的位置和尺寸与原型相差均在 1 CSS 像素内（测试断言）。
- 菜单、对话框、搜索面板、联想面板、选集列表与播放页合计 40 个被测盒子，与原型相差最大 0.58 像素（最终一轮；此前各轮最大 0.96）。

实现期间对原型行为做的最小偏离，依据都在上文“歧义与最小处理依据”：

| 偏离 | 原因 |
| --- | --- |
| 清晰度按钮只在片源真有两档以上时出现 | 契约规定；原型的四档是演示 |
| “跳过片头”按钮只在片源给出片头标记时出现，不使用固定 90 秒 | 实测的真实片源都不提供片头标记，不伪造 |
| 筛选行默认显示前 12 项（地区 9 项），行尾“展开/收起” | 用户追加的完整筛选词表（每频道 127–171 项）平铺会把片单挤出首屏；展开按钮沿用原型的文字按钮样式 |
| “检查更新”在未配置更新地址时提示“更新服务未配置” | 没有发布服务，不能复制原型的“已是最新版本” |
| 热搜、推荐、演职员等任何一块取不到数据时显示错误与重试，或整块不出现 | 不用演示数据补位 |
| 没有已保存首页的那一次启动（安装后第一次、或保存内容已不可用），主推区与第一栏先出现，下方栏目按页面顺序自上而下补上；之后的启动整页一次出现 | 原型的首页是一次出现的演示数据。等全部 10 个接口返回再显示就是用户报告的启动卡顿；栏目只在已显示内容的下方追加，已显示的内容不移动（2026-11-17，[记录](../.agents/notes/implemented/architecture/2026-11-17-startup.md)） |
| 播放器控制栏多一个“线路”菜单（有两个以上的源收录这一集时出现） | 用户要求“随便点一个都能播”：自动换源之外给一个手动出口；沿用原型清晰度 / 倍速菜单的同一个 `SelectMenu` 与按钮样式，不新增样式 |
| 清晰度标签显示从片源首片读到的实际画面，而不是清单里声明的 | 清单声明实测不可信（声明 1080x608 实际 1920x1080）；读不出时不显示 |
| 选源失败时先保持加载状态自动再要 2 次，之后才出现原型的错误态 | 多数失败是网络一时不通；错误态本身的样式、文案位置与原型一致（19 号场景对照，差异 0.17%） |
| 详情页的演职员头像显示照片，有豆瓣人物 id 的人可点（2026-11-17） | 用户要求照片和按人找作品。圆框、姓名、角色仍是原型的 `.cast*` 样式；照片顶端对齐，外圈线画在照片上面（原型把线画在内容下面，照片会盖住），可点的人获得焦点时头像外圈用主题色描边，悬停时照片微放大，与海报卡一致。没有 id 或照片的人与原型完全相同（原型对照用的演示数据即是如此），[记录](../.agents/notes/implemented/architecture/2026-11-17-people.md) |
