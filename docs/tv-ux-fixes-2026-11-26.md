# TV 端修复与验证

2026-11-26 对本地 TV 1.0.14 完成修复。复测使用签名 release APK、Android 15 模拟器和遥控器按键。首页与搜索使用真实元数据，播放检查使用国产《三体》第 1 集。目录响应顺序、媒体故障和章节时间另用可重复的网络响应验证。[原问题报告](tv-ux-audit-2026-11-26.md)

| 原操作 | 修复与验证 |
| --- | --- |
| 首装首页向下浏览 | 并发获取各栏目，按响应顺序合并，最终页面保留完整结果。首要栏目之一失败时仍展示可用内容。全新安装的首个会话已用方向键经过榜单、最新电影、综艺、动漫并抵达纪录片。单元测试另覆盖新片榜返回 404。 |
| 播放错误页按“重试”，或起播时按返回 | 用户重试可以重新探测冷却中的线路。退出播放器或竞速选中其他线路不再把取消记成片源故障。两条测试线路先返回 503，恢复后一次确认键产生 **15 个新的媒体请求**，约 **1.15 秒**恢复到可读播放时钟。另验证中途退出后另一部作品仍能使用同源。 |
| 检查片源超时、短暂起播后退出 | 目录单次查询的期限覆盖等待和阻塞 I/O，各源可独立返回。实际剧集起播后，曾经发生的错误还涉及低缓冲判断误将仍在前进的画面当成故障。现按播放进度和实际缓冲状态决定是否恢复，探测替代线路期间可保留原画面。最终实播在首次点击约 **6.04 秒**后走到第 1 秒，继续播放到 **02:00 / 42:44** 后由测试按暂停结束。 |
| 《三体》红牛版本出现博彩推广 | 第 1、2、3 集片头，以及第 1 集片尾的抽帧均观察到推广叠字，前三集清单均无分片中断标记。TV 与桌面现在都在同名候选截取之前排除红牛收录 `71759`。同一作品仍通过其他合格收录选播。最终 APK 的发行许可画面已通过另一份拷贝播放。[原收录的片头与片尾抽帧](evidence/tv-ux-fixes-2026-11-26/promoted-edition.webp) |
| 慢目录补充集数和线路 | 同一个查询向详情和播放器提供首批与完整结果。受控回放中，详情先展示播放操作，约 **7.91 秒**后原页出现第 1 至 5 集；播放器先起播，随后在原页面出现“选集”和“线路”。已点选而首批目录缺少的集数会等完整结果。 |
| 在目录冷却期间反复重试 | 冷却期间被跳过的查询不再刷新计时。可控时钟用例让目录失败三次，在第 16 秒重试仍保持原期限，上游恢复后第 31.5 秒发起真实目录请求并成功。 |
| 打开长简介详情 | 播放和收藏放到片名、评分与年份之后；初次进入时保留顶部可见。release APK 上的《三体》和《八仙！》均能同时看到片名与主操作。 |
| 在设置清空搜索记录，再返回原搜索页 | 搜索页重新显示时核对已保存的最近记录。原页立即移除了旧词。 |
| 在已有结果上退格删完，再按返回 | 编辑中的空文本保留之前已提交的查询、结果与类型筛选。遥控器实测恢复了 `ST`、类型筛选和结果 `S/T`。显式“清除”仍可清空当前输入。 |
| 进程被系统回收后返回 | Android 的保存状态记录页面栈、条目标识、浏览位置和焦点。实际回收到新进程后，仍在同一 Android 任务中恢复《八仙！》详情及“收藏”焦点，按返回又回到首页动漫栏的同一张卡片。 |
| 自动跳过片头片尾 | TV 读取具有时间锚点的 HLS 日期范围和 MP4 Nero 章节。播放期间执行片头跳转，并在已标记的片尾按自动连播设置推进或结束。受控视频在第 4 秒结束片头、第 20 秒进入片尾、总长 28 秒，HLS 已跳过片头并在片尾进入下一集，MP4 也已从片头跳到第 4 秒。没有随流标记时，观众可在播放器“片头片尾”按当前位置标记或清除；手动标记用于当前作品和线路。设备回放验证记住第 15 秒，重新进入同一集时自动跳过。关闭自动跳过和连播后，同一片源从第 0 秒播到第 22 秒，保留了第 20 秒开始的片尾。 |
| 在设置检查更新 | 实际请求官方 GitHub Releases，按已发布稳定版的 TV APK 附件比较版本。设备查到已发布的 1.0.14 并反馈“已是最新版本”。版本比较测试覆盖较新版、桌面安装包、草稿、预发行、未签名附件和异常返回。 |
