# Windows 与 TV 质量复核

本轮以 11 月 26 日的工作区为起点。提交 `a5f779c` 收录已有的播放对齐、片源健康记录、TV 导航和测试。下表记录在这份基线上继续定位的问题。

| 场景 | 原行为 | 修复与验收方法 |
| --- | --- | --- |
| Windows 首页轮播 | 悬停、键盘焦点和手动暂停共用同一状态。补到的栏目也会把推荐切回第一部。 | 按作品 ID 保留选择。悬停和焦点只暂停计时，手动暂停持续到明确恢复。系统减少动效时可手动翻片。通过真实组件和首页 IPC 刷新回放验证。 |
| 最小窗口叠加 150% 页面缩放 | 两个绝对定位区争用首页宽度，背景图的放大还会使隐藏区域发生横向滚动。 | 文案和翻页器纳入同一 Grid，紧凑宽度下换行，海报改为四列。测量 720 CSS 像素视口的边界和控件命中，并用 Electron 原生窗口截图核对完整画面。 |
| 冷启动与目录更新 | 新片榜失败会盖住仍可用的剧集。较慢的目录补到后，已打开的选集和线路面板仍显示首批数据。 | 任一主要栏目可用即可展示首页。新增目录按作品通知页面，已有剧集按编号保留焦点。请求首批没有的集数时等待同一轮完整结果。网络边界回放覆盖从 3 集扩到 5 集、补充线路与播放继续。 |
| HLS 与首屏资源 | 缓冲不足 6 秒时，持续前进的画面也可能被判为故障。此前首页还会载入整套播放器。 | 低缓冲同时检查播放时钟、实际等待状态、替代线路和补充缓冲的时间。2 秒 HLS 分片延迟 1.7 秒返回时，原线路可连续播放。播放器按路由载入，首页入口 JavaScript 从约 1.11 MB 降至约 0.47 MB，均为构建后未压缩字节数。 |
| 跳过片头片尾 | 桌面播放器会读取章节字段，但原先主进程没有填充这些字段。 | 主进程从带时间锚点的 HLS 点播清单、或已读取的 MP4 文件头内的 Nero 章节提取时间点。关闭连播时，跳过片尾会正确结束当前集。Windows 对仅在 MP4 文件尾部的章节仍按普通视频播放，TV 另支持片尾范围读取和手动标记。 |
| Windows 检查更新 | 默认安装后缺少额外环境变量，设置页无法核对版本。 | 默认读取官方稳定 Release 中已上传的 Windows 安装程序。TV APK、草稿、预发行和空附件均不参与桌面版本比较。保留自有 HTTPS 清单。实查返回已发布的 1.1.4。 |
| TV 遥控器与首页布局 | 整组栏目变化时可能全量刷新，旧的“继续观看”请求也可能回填页面。首页翻片箭头在无障碍树中没有名称。 | Leanback 首页用 RecyclerView DiffUtil 按稳定栏目 ID 更新，取消已过期的历史请求。翻片控件有可读名称，系统关闭动效时自动轮播停止。遥控器实测能手动从 1/5 切到 2/5，再将焦点移到顶栏，8.5 秒后仍停留在 2/5。 |
| 两端元数据落盘 | 超限时每丢一条记录就重新编码整份 JSON，单条过大的记录还会挤掉其他作品。TV 并发落盘存在旧快照覆盖新快照的窗口。 | 按 UTF-8 字节从近期记录选取可容纳的完整条目。TV 写入串行化并原子替换文件。两端的重启回归均验证了超大中文简介、保留顺序和读取结果。 |

## 验证范围

Windows 使用 Node 24、Electron 45、真实渲染器和本地生成的可解码视频。联网回放通过正常搜索入口进入国产剧《三体》，验证选集、跳转、退出和重新进入。可重复的多线路故障及不同剪辑版本使用网络边界回放。

| 本地检查 | 结果 |
| --- | --- |
| TypeScript、Vitest、发布工具 | 类型检查通过，139 项单测及 6 项发布工具测试通过。 |
| Windows 界面与打包 | 19 项离线 Electron 回归通过。生成 x64 NSIS 安装程序，检查 asar 中的 273 项。以打包后的 Panda.exe 运行真实网络测试，2 项通过。电影频道从 30 张实际影片卡片加载到 60 张，计数排除了加载占位卡片。 |
| Android TV | 160 项 JUnit 全部通过。兼容性 lint 为 0 个错误、32 个警告。release APK 通过 v1 和 v2 签名校验。 |
| 规则同步 | 重新导出 TV 黄金向量和规则资产后 Git 差异为空，规则参数检查通过。 |
