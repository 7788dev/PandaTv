# Agent Note: 去广告以清单内证据为准，规则不联网更新

Status: implemented

## Problem

最初沿用参考项目的做法：规则绑定“已验证 CDN 域名”名单，并带一个到期日。复审时 82 份线上清单只有 15 份被过滤——每个源都在轮换 CDN 域名，名单几周就失效；到期日只和日历有关，到期后规则静默全关。带 AES-128 的清单被整份跳过，而广告正是以明文块插在加密正片里。

## Decision

规则只按源 key 生效，删除依据必须来自清单结构本身，共五类：闭合的 CUE 区间、CMS 广告标记、源专用广告目录前缀、已截帧确认的时长指纹、正片目录之外的短块。逐段跟踪 `#EXT-X-KEY`，只在不影响解密时删除。保护条件（直播、BYTERANGE、MAP、未闭合区间、删除比例超过 15%、单块超过 90 秒等）触发时整份原样返回并输出诊断。规则随发行包发布；用户数据目录的 `play-sources.json` 通过同一校验且版本不低于内置时取代内置规则。逐条事实、样本与实测结果在[播放审阅](../../../../docs/playback-audit.md)，可用 `npm run audit:ads` 重放。

## Alternatives considered

- 继续维护 CDN 域名名单：实测失效速度快于发版速度。
- 按路径或文件名里的 ad/gg/promo 字样、按“短块”或“重复块”删除：正片自身会被切成几十到几百个短块，误删风险无法约束。
- 规则设有效期：过期与规则是否正确无关，表现为某天起广告全部回来且无提示。
- 从网络拉取规则：规则决定访问哪些主机、删除哪些分片，远程下发等于把这两件事交给第三方；本项目也没有可签名的发布服务。
- 加密清单一律不处理（原实现）：bfzy、360zy 的广告因此全部保留。

## Consequences

指纹只认截取过的广告，源方更换广告后会漏删但不会误删，需要重跑审计补指纹。正片目录内的短块没有证据，保留。审计结果随线上内容变化，文档中的数字以 [ad-audit.json](../../../../docs/evidence/ad-audit.json) 的时间戳为准。
