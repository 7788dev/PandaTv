# Agent Note: 豆瓣条目与片源记录的身份匹配

Status: implemented

## Problem

播放源按片名检索，返回的记录只有片名、年份、分类和选集列表。原匹配要求片名（含季）、年份、分类全部一致，实测有四类条目因此播不了或播错范围：

- 豆瓣把长篇连载按年拆成条目（《凡人修仙传 年番4》2026，52 集），片源只有一条累计记录（《凡人修仙传》2020，200 集）。
- 一个源在同名记录下多列了后续内容，或在一条线路里混入特别篇；原逻辑取条数最多的线路做选集基准，其余源的编号线路全部作废。
- 豆瓣与片源的年份差一年（《生命奇观》2023 / 2024），或片源用的是别名、港台译名。
- 豆瓣标题末尾带零宽字符。

## Decision

身份仍然是“名称 + 年份 + 分类”三者互证，名称单独不成立。在 [service.ts](../../../../src/main/playback/service.ts) 里分三级证据：

1. 标题一致且年份、分类一致（原规则）。
2. 连载区间：豆瓣详情 `aka` 中的“X 第N-M集”说明条目是连载 X 的第 N…M 集。记录名为 X、分类一致、年份不晚于条目（N=1 时必须同年）即接受，只取线路上带编号的第 N…M 集并从 1 重新编号（线路里少量无编号的附加项如“90分钟结局”“第240集上/下”跳过，重复出现的编号不用；带编号的条目不足九成的线路不用）；区间终点取别名与豆瓣集数两者中较长的一个。找到区间记录后，其他同名记录截到同样集数，无编号列表不参与。
3. 弱匹配：别名（去掉“(港)”“(台)”标注）一致且年份、分类一致；或标题、分类一致而年份只差一年。弱匹配只在 1、2 都没有结果时使用。

选集基准线路只在“逐集编号”或“每项都有自己名称”的线路中选最完整的一条；只是顺序的混合列表仅在别无选择时使用。比对与检索前去掉零宽与方向控制字符。别名由豆瓣适配层随详情写入元数据存储，经 IPC 层的 `hints` 传给播放服务，不进入渲染器契约。

## Alternatives considered

- 按“年番/第N季”的序号推算累计集数：各系列每年集数不同（24、28、52、62），推算必错；豆瓣别名给的是明确区间。
- 只用标题检索累计记录、不截取区间：会把整部连载列在每个分年条目下，第 1 集对应的是连载第 1 集而不是该条目的第 1 集。
- 接受按别名找到的分篇记录并与区间记录混用：分篇的起点不一定等于条目起点（一个条目可含两个分篇），不同线路同一集号会指向不同内容。
- 年份放宽到 ±1 且与精确匹配同等对待：同名、同类、相邻年份的不同作品虽少见，但一旦混用就是播错片；因此降为只在没有精确匹配时使用。
- 取条数最多的线路做基准（原实现）：特别篇、重复项会让一条不可靠的线路排除所有编号线路，实测导致《斗破苍穹 第一季》无法播放。
- 区间只取“每一项都有编号”的线路（最初的实现）：实测《斗罗大陆》的累计记录在 6 个源里有 5 个夹着两三个附加项，结果分年条目只剩一个源可用，该源媒体主机一抖动整季就播不了。
- 用豆瓣集数截断所有标题匹配的记录：豆瓣集数对在播作品常常滞后，截断会藏起真实可播的新集。

## Consequences

六个长篇系列的分年条目可播且集数与豆瓣区间一致，热门内容覆盖率与证据见[播放审阅](../../../../docs/playback-audit.md)和 `npm run probe:sources`（[结果](../../../../docs/evidence/source-coverage.json)）。没有区间别名的条目仍只按标题匹配：累计记录会把全部集数列在第一季条目下。位置式（无编号）线路无法映射区间，不参与分年条目；被拆成上下两段的一集在该线路上没有对应项，由其他线路提供。没有任何源答复时的结论见[片源结论](2026-11-16-source-verdict.md)。回归在 [source-alias.test.ts](../../../../tests/source-alias.test.ts) 与 [source-match.test.ts](../../../../tests/source-match.test.ts)。端口策略的相关决定见[媒体端口](2026-11-16-media-ports.md)。
