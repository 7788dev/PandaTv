# Agent Note: 起播选源先看播放余量，再看实际画面

Status: implemented

## Problem

起播原先按配置里的优先级依次试源，先交出分片的赢。实测有三个问题：

- 哪个源快取决于观众在哪。本机代理出口在境外时 360zy 最快、国内几家 CDN 慢；在北京的服务器上 360zy 的域名解析到 `127.0.0.2`（完全不可用），而速播/虎牙最快。固定排名在其中一处必然是错的。
- 清单里写的分辨率不可信：量子资源声明 1080x608 的清单里实际是 1920x1080，非凡声明 1080x608、实际 1920x800；同一个源不同作品也不同（《奥德赛》在“金鹰系”各源是 864x326 的影院录制，量子/电影天堂是 1920x1080）。按声明或按源挑清晰度都会挑错。
- 一个又慢又不报错的源占着名额，后面的源等它超时才轮到。

## Decision

[service.ts](../../../../src/main/playback/service.ts) 的 `choose` / `contest` / `probe`、[delivery.ts](../../../../src/main/playback/delivery.ts)、[picture.ts](../../../../src/main/playback/picture.ts)，TV 的 [DeliverySpeed.kt](../../../../tv/app/src/main/java/app/panda/tv/playback/DeliverySpeed.kt) 使用相同规则：

- 画面大小从第一个分片的开头读（MPEG-TS 里的 H.264 SPS，最多读 64 KB）；整片 AES-128 加密的先用清单里的密钥解开开头。读到的密钥和分片交给媒体代理，播放器再要时不重新下载。源只提供一种清晰度时，界面上的清晰度标签就是读到的画面。
- 同时问 3 个源；一个源 2.5 秒没交出整个首片就让出名额（继续在后台下载），最多 8 个同时在途。
- 2026-11-18 增加播放余量：以首片实际媒体时长除以从连接开始到下载的耗时，得到每秒下载了多少秒媒体。流式下载时只在有长度证据时按已下载比例估计；不知道时长或长度时记为未知。余量至少 1.25 倍的源优先，再比较实际画面；未知源排在已测不足的源之前；全部不足时先比较余量。这个阈值是选源的保守余量，不保证源之后永不拥塞。
- 交出完整首片、画面达到所要清晰度（未指定时 1080P）、且余量达标的源直接赢。画面较小、未知或余量不足的先留着，1.5 秒内没有更好的就用其中最合适的；留着的不到 720P、且有别的源正在下载时，再等一次 1.5 秒，只等一次。
- 最后一个开始的源也满 3 秒仍没有完整首片时，对已交出媒体开头的源使用相同余量与画面顺序；相同分值时比较实际下载速率。
- 会话内记住“这里慢”的源 10 分钟（探测失败、占满一轮没交出、已测余量不足、观众手动重试离开的），排到其余源之后；交出首片且余量没有不足时恢复。
- 全部失败时，对连接被重置/超时这类失败再比一轮，仍失败才报错。播放器收到“暂时无法连接”这类结果会自己再要 2 次（间隔 0.8 秒）才显示；“没有片源/没有这一集”立即显示。
- 片源目录搜索：找到作品后，其余目录最多再等 1.2 秒，上一次搜索失败的目录不等；迟到的答复写回缓存，补进线路列表。

片源表 [play-sources.json](../../../../resources/play-sources.json) v3 增加速播、虎牙、红牛，停用飘零（接口答复 `closed`）；极速仍停用（[playback-audit](../../../../docs/playback-audit.md) 里记录过串片）。优先级只决定先问谁。

依据（北京阿里云服务器，2026-11-17，探针与结果见 [cn-sources.md](../../../../docs/evidence/cn-sources.md)）。

## Alternatives considered

- 按地区写两套固定排名：需要判断观众所在网络，而且源的快慢一天之内就变（同一台服务器 06:46 搜索中位数 0.6 秒，14:17 有目录三分之一的请求拖满 9 秒）。
- 只按速度选：最快的常是 480P/606p 的量子线路，观众得到的是能看但模糊的画面。
- 只要下载到高清首片就立刻选它：短首片能很快结束，却可能没有足够传输余量支撑连续播放。改为在余量达标的源里比较实际画面。
- 用清单声明的 RESOLUTION 或码率判断清晰度：实测声明与实际不符（见上）。
- 等所有源答复后挑最好的：起播要多等最慢的源，最坏 10 秒。
- 用 ffprobe 读画面：要随安装包带一个二进制，只为读一个 SPS。
- 把 360zy 在国内停用：它在境外出口最快，停用就是让那部分观众变慢；改为识别“域名解析到非公开地址 = 此网络到不了”，见[片源结论](2026-11-16-source-verdict.md)。

## Consequences

第一部片子可能多花一两秒试探，之后同一会话里慢的源排在后面。足够流畅的较低清晰度可能先于已测不足的高清源被选中。H.265 或 fMP4 分片读不出画面，按“未知”处理（介于 480P 与 720P 之间），不会被误标清晰度。改动选源、线路编号后按 AGENTS.md 运行 `npm run probe:sources` 和 `npm run probe:start`；回归在 [playback-start.test.ts](../../../../tests/playback-start.test.ts)、[picture.test.ts](../../../../tests/picture.test.ts)、[source-requery.test.ts](../../../../tests/source-requery.test.ts)，并重导 TV 黄金向量。最终运行数据与网络限制以[交付报告](../../../../docs/delivery-report.md)为准。
